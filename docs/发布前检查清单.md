# QDIP 发布前检查清单

面向维护者的发布前逐条检查。本文件留在仓库，不随整合包分发；玩家上手与故障排查见 `templates/玩家使用指南.md`，本文件不重复。

- 每条格式：`- [ ] <做什么> —— <命令> —— <期望>`。
- **[必跑]** 是发布阻断项；**[建议]** 可视改动范围取舍。
- 命令一律从仓库根执行；`<version>` 取自 `tools/components.json` 的 `version`（当前 `0.4.0`）。

- [ ] **[必跑]** 处理版本闸门失败 —— 若上一步非 0，按输出的 `[HINT]` 处理：把对应版本的制品放入 `tools/cache/` 并按 `components.json` 的 `source` 命名；若制品本身已更新，则改 `components.json` 里该组件的 `version` —— 重跑上一条恢复退出码 0。

- [ ] **[必跑]** 产物校验器、启动器环境模块与文档校验器单测 —— `node --test "tools/*.test.js"` —— 全绿 40 例（`pass 40` / `fail 0`）。
- [ ] **[必跑]** 文档/地图层单测（路径引用 + 编码 + BOM） —— `node --test "tools/check-docs.test.js"` —— 全绿 16 例（`pass 16` / `fail 0`）。校验的是文档层的**路径引用**（反引号包裹的路径候选必须能在某个基准上解析：仓库根 / 产物根 / basename 索引）与**编码约定**（`.bat` 按 GBK、`.ps1` 必须带 UTF-8 BOM、其余 UTF-8 不带 BOM；禁止 U+FFFD 与私用区字符）。**建议在组装（第 2 节）之后跑**：产物路径相对最新 `build/qdip-generic-*` 解析，没有产物时整类跳过——`node tools/check-docs.js` 会打印 `[SCOPE]` 与 `[WARN]`，可用来确认产物路径确实被核对了。已知盲区：含 `*`/`?` 的 glob 片段、含 `...` 的省略写法（`tools/cache/...`）、含 `<...>` 的占位符（`opencode-<version>`）不检查；`CHANGELOG.md` 只查编码不查路径（历史记录里的旧文件名允许已不存在）；历史规划文档（`docs/00-*`/`docs/01-*`/`docs/02-*`、`docs/matt-pocock-workflow-report.md`、`docs/workflow-diff-and-recommendations.md`、`docs/agents/*`）不在路径检查范围内。

## 4. 产物校验器单独跑一次

- [ ] **[必跑]** 用产物内便携 Node 直接核对产物 —— `build\qdip-generic-<version>\runtime\node\node.exe tools\verify-package.js --out build\qdip-generic-<version>` —— 输出 `[OK] package verified: <outDir>`，退出码 0。
- [ ] **[建议]** 认识退出码语义 —— 无需命令 —— `0` 全绿；`1` 有违规（按 rule 分组打印 `[FAIL] <rule> (n)`）；`2` 参数缺失或读不到 `components.json` / `layout.json`。

## 5. 启动器自检

- [ ] **[必跑]** 在产物目录运行启动器自检 —— `cmd /c "build\qdip-generic-<version>\启动.bat --check"` —— 退出码 0，且无任何 `[FAIL]` 行。
- [ ] **[必跑]** 注意 `--check` 必须带参数运行 —— 双击 bat 不会传参（Windows 双击等价于无参启动，会走正常启动流程而非自检） —— 必须在 cmd/PowerShell 里以带参数方式调用，如上一条命令。

自检会检查的项：

- node 路径（`runtime\node\node.exe`）与版本（`node.exe --version`）
- opencode 插件加载（`opencode debug agent orchestrator`）
- Windows Terminal 发现（`:find_wt`；找不到时打印 `[WARN]` 并回退普通控制台）
- 工作目录（`WSDIR` 是默认包根还是玩家设定）
- 缺失项 `[FAIL]`：`node missing`、`opencode missing`、`env.bat missing`、`oh-my-opencode-slim NOT loaded`、`wt-profile.ps1 missing`

说明：自检只诊断玩家机器上的运行时依赖，不再检查产物文件是否存在。**代码页陷阱**：cmd 按*当前控制台代码页*解释批处理文件里的字节，含中文的文件名字面量在 UTF-8 控制台（`chcp 65001`）下会被错误解码而误判（原先的 `进入环境.bat missing` 项即因此误报，已移除）；因此批处理里不要出现含中文的文件名字面量。launcher 文件完整性由构建期把关——`tools/build.ps1` [3/5] 的源存在性断言与产物侧 `layout/deploy-missing` 双重覆盖。

## 6. 首次引导冒烟

- [ ] **[必跑]** 起引导服务并验证引导页返回 200 —— 见下方 PowerShell 片段 —— 打印 `STATUS=200`。

```powershell
$root = (Resolve-Path "build\qdip-generic-<version>").Path
$node = Join-Path $root "runtime\node\node.exe"
$urlFile = Join-Path $root "data\.guide-url"
if (Test-Path $urlFile) { Remove-Item $urlFile -Force }
$p = Start-Process -FilePath $node -ArgumentList @((Join-Path $root "setup\guide-server.js"), $root) -PassThru -WindowStyle Hidden
$deadline = (Get-Date).AddSeconds(15)
while (-not (Test-Path $urlFile) -and (Get-Date) -lt $deadline) { Start-Sleep -Milliseconds 300 }
if (-not (Test-Path $urlFile)) { Stop-Process -Id $p.Id -Force; throw "引导服务未写出 data\.guide-url" }
$url = (Get-Content $urlFile -Raw).Trim()
$status = (Invoke-WebRequest -UseBasicParsing $url).StatusCode
Stop-Process -Id $p.Id -Force
"URL=$url STATUS=$status"
```

步骤：启动 `setup\guide-server.js <产物根>` → 服务在系统随机空闲端口监听并写出 `data\.guide-url`（内容形如 `http://127.0.0.1:<port>/setup/first-run.html`）→ 请求该 URL。该片段已实测输出 `STATUS=200`。

- [ ] **[建议]** 清理冒烟残留 —— 无需命令 —— 冒烟只在产物目录 `data\` 下留下 `.guide-url`（不影响已生成的 zip，下次构建 [1/5] 也会清理）；如介意可手动删除。
