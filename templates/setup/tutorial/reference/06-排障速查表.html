B改配置三原则

1. 先备份

动任何配置文件之前，复制一份带日期后缀的备份（*.bak）——出事能一秒回滚，这是最便宜的安全网。

2. 最小修改

一次只动一处。改两处，出了问题分不清是谁的锅。

3. 新会话生效

配置改动在新会话或重载后才被读取。改完没反应，先别慌——开个新会话试试。

省心做法：在对话里说“帮我改配置”，系统会走配置车道（customize-opencode）——自动备份、窄修改、提醒你生效条件。

C三层定位法

遇到没见过的症状，按这个顺序想，不要瞎试：

定位顺序
1 哪一层？   # 规则（宪法层）/ 技能没触发（技能层）
              # 代理·模型（编排层）/ 终端·会话（本体层）
2 哪个文件？  # 到第 5 课文件地图里找对应那一行
3 最小修改   # 改一处 → 开新会话 → 看症状是否消失
              # 没消失就回滚备份，换一个假设

别瞎试

一次改多处、不回滚、靠重装——都只会制造新问题。

D配额事件要点

2026-09-16 真实案例（派给 designer 的任务卡死）的四步复盘：

一次真实的配额事件
症状  designer 任务卡死不动（等了几分钟没产出）
定位  不是任务本身——该代理服务商额度耗尽（配额层）
处理  备份配置 → 换 designer 的模型 → 清掉卡死任务 → 继续
收尾  核对已完成产出（别浪费）→ 记录到工作笔记

三条教训

①配额按服务商算——一个代理的额度影响所有用它的任务；②备份是安全网——换模型前先留退路；③换模型不用重装——一行配置的事。
