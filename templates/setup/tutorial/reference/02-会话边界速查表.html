A五种换台方式（按序选第一项合适的）

方式何时选它代价操作
1. continue 会话仍是第一手来源（阶段未结束、活没干完） 无 不动
2. clear 到了阶段边界，且该落盘的都落盘了 丢掉未落盘的一切 /new（别名 /clear）
3. handoff 仅搬迁：换 harness、换目录、交同事 要生成并阅读文档 /handoff 技能
4. subagent 范围足够紧、能 AFK 跑 需交代清楚任务包 丢给子代理后台跑
5. compact 最后手段：不想丢链条又必须腾空间 信息有损 /compact（别名 /summarize）

B阶段节奏（多窗口任务）

边界画在工单之间
grill-with-docs → to-spec → to-tickets
# 同一会话，不中断
──────── 边界：工单已落盘 ────────
implement 工单 1   # 新会话
──────── 边界 ────────
implement 工单 2   # 新会话

数字底线

单会话健康上限约 150K token（smart zone 边界）。到了这个量级，换台是必选项。

C三条铁律

落盘先于换台

文件是耐久记忆，会话是可抛弃的。spec、工单、笔记写进磁盘，会话才允许死。

边界只在阶段边缘

活干到一半别换台。换台时刻：阶段结束、工单完成、决策拍板。

compact 是最后手段

先问能不能 clear（干净重启，零信息损失）；不行才压缩。

D操作速记

操作命令快捷键
开新会话/new（/clear）ctrl+x n
找回 / 切换会话/sessions（/resume）ctrl+x l
压缩当前会话/compact（/summarize）ctrl+x c

干净重启不等于烧掉记录——旧会话随时可从 /sessions 找回。

E常见误用

误用后果正确做法
该换不换 AI 健忘、跑偏、变贵 到阶段边界就换，别恋战
不该换乱换 线索断裂，背景重讲 活干完再换；先落盘再换
拿 compact 当默认 信息有损，细节丢失 能 clear 就别 compact
