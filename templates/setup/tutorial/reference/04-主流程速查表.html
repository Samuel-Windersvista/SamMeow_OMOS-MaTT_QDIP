A主链五站全表

每一站的箭头都对应一个落盘产出；小任务走折叠版。

站点在做什么产出物（落盘）你的动作
grill-with-docs 追问钉清目标与关键决策 GLOSSARY.md、ADR（决定记录） 回答追问、拍板
to-spec 把对话综合成规格 spec 文档 过目确认：有没有漏掉你的意思
to-tickets 拆成垂直切片工单 工单列表（每张可独立演示） 检查粒度：每张是不是完整的小功能
implement 按工单实现（内驱 tdd） 代码、测试、提交 在工单边界开新会话（第 2 课）
code-review 双轴审查：仓库标准 + 原始规格 并排审查报告 看报告，决定放行还是返工
复盘（retro / reflect） 回顾这次工作，提炼改进 改进建议、可复用资产 一句话触发，翻一翻建议

B链路图

主链路 -- 多窗口任务
grill-with-docs  → 追问钉清；边问边写 GLOSSARY.md / ADR
      ↓
to-spec          → 综合成规格文档（不再追问）
      ↓
to-tickets       → 拆成垂直切片工单（每张可独立演示）
      ↓
implement ×N     → 每张工单：内驱 tdd，收尾 code-review
折叠版 -- 单窗口任务
grill-with-docs → implement
# tdd 与 code-review 在 implement 内部自动跑完

流程不是仪式——按任务重量裁剪，这正是第 1 课分拣站的意义。

C三个关键原则

一次问清胜过十次返工

grill 环节不许跳。目标模糊时先追问，是这套流程最值钱的习惯（第 1 课的心法一）。

落盘是流程的载体

GLOSSARY.md、spec、工单——每一步的成果都是文件。所以换会话不可怕（第 2 课），流程接得上。

每站都有“完成信号”

能说清“这一步完了”再往前走——spec 确认了、工单检查过了、审查报告看了。含糊过关，后面会加倍偿还。

D复盘：让系统变聪明

收尾不是“做完就散”——两个复盘技能让这套系统从每次工作里学习：

两个复盘技能
retro    # 回顾会话，按类别提改进建议（流程 / 检查 / 标准）
reflect  # 发现重复劳动，建议沉淀成可复用资产（技能 / 配置 / 模板）

你的动作只有一句话

说一句 “复盘一下”。建议由它出，采不采纳你说了算——把经验变成文件。
