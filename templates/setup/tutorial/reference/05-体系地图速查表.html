A文件地图全表

想改什么，先去哪——路径以本机为准（~ 即用户主目录）。

你想改什么去哪个文件 / 目录层级
规则：入口判定、会话边界、委派 ~/.config/opencode/preferences.md 宪法层
预设、各代理的模型、议会席位 ~/.config/opencode/oh-my-opencode-slim.json 编排层

技能（工程流 39 个 + OMO 内部 9 个） ~/.agents/skills/ 与 ~/.config/opencode/skills/ 技能层

出事后回滚配置 同目录的 *.bak 备份文件 宪法 / 编排层

B五层结构

体系结构 -- 五层（上面定方向，下面干活）
[宪法层]  preferences.md        ← 规则：入口判定 / 会话边界 / 委派
[技能层]  SKILL.md × 48         ← 流程与工具（两处目录）
[编排层]  OMOslim 插件          ← 预设 / 代理 / 模型 / 后台任务
[本体层]  opencode              ← 终端 / 会话 / TUI 命令
[外援层]  MCP                   ← 外部工具（浏览器、Blender…）
层一句话
宪法层你写的规则，最终裁决一切流程问题
技能层一叠说明书（grill、spec、fix……），按需加载
编排层工头与代理团队的家，模型与预设的配置处
本体层真正跑在你电脑上的程序：终端、会话、命令
外援层给 AI 接的外部工具（浏览器自动化、Blender 控制）

C预设与模型要点

要点说明
预设是什么 一整套“代理 × 模型”的组合方案
当前激活 matt-bridge（配 Matt 工程流技能）
备用方案 DeepSeek-Only、superpowers-bridge
切换方式 TUI 里用 /preset——重载后才生效
模型分配 预设里逐一定义：搜索类配快模型、决策类配强模型
花销与余量 看侧边栏用量条（opencode-quota 插件），按服务商显示剩余额度

D一句话任务的旅行

你说一句“给整合包做个小工具”，五层依次接手：

五步旅行
1 宪法层  # 定路线：入口判定 → 单窗口任务
2 技能层  # 加载说明书：grill → implement
3 编排层  # 工头拆活，需要时派代理（新会话 = 新工作台）
4 本体层  # 真的读写文件、跑命令、管理会话
5 外援层  # 需要查文档、看截图时，调用对应工具

每一层各司其职——所以出问题时，也是按层定位（第 6 课的分诊表就建立在这张地图上）。
