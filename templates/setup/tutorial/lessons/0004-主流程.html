LESSON 04

主流程：从追问到验收

预计 15 分钟 | 难度：进阶 | 前置：第 1 课 · 第 2 课 | 更新于 2026-09 | 适用版本：QDIP 0.6.0（环境快照 2026-09-30） 主流程

第 1 课说"单窗口任务走 grill → implement"； 这一课把这条链拆开，逐站看：发生什么、产出什么、你要做什么。 看完你会明白：为什么这套流程敢让你"只描述需求"。

4.1完整链路

多窗口任务的完整主链路——注意每一站的箭头都对应一个落盘产出：

主链路 -- 多窗口任务
grill-with-docs  → 追问钉清；边问边写 GLOSSARY.md / ADR
      ↓
to-spec          → 综合成规格文档（不再追问）
      ↓
to-tickets       → 拆成垂直切片工单（每张可独立演示）
      ↓
implement ×N     → 每张工单：内驱 tdd，收尾 code-review

单窗口任务就是这条链的折叠版：grill → implement （tdd 与 code-review 在 implement 内部自动跑完）。 流程不是仪式——按任务重量裁剪，这正是第 1 课分拣站的意义。

4.2逐站拆解：产出物与你的动作

表 4-1 · 每一站：它在做什么、留下什么、你做什么
站点它在做什么产出物（落盘）你的动作
grill-with-docs 追问钉清目标与关键决策 GLOSSARY.md、ADR（决定记录） 回答追问、拍板
to-spec 把对话综合成规格 spec 文档 过目确认：有没有漏掉你的意思
to-tickets 拆成垂直切片工单 工单列表（每张可独立演示） 检查粒度：每张是不是完整的小功能
implement 按工单实现（内驱 tdd） 代码、测试、提交 在工单边界开新会话（第 2 课）
code-review 双轴审查：仓库标准 + 原始规格 并排审查报告 看报告，决定放行还是返工
复盘（retro / reflect） 回顾这次工作，提炼改进 改进建议、可复用资产 一句话触发，翻一翻建议

为什么是"双轴"审查

一条轴对照仓库标准（代码风格、既有约定），一条轴对照原始规格 （是不是真做了当初要的东西）。两轴并行审、分开报告——不会互相掩盖问题。

4.3三个关键原则

  1. 一次问清胜过十次返工：grill 环节不许跳。 目标模糊时先追问，是这套流程最值钱的习惯（第 1 课的心法一）。
  2. 落盘是流程的载体：GLOSSARY.md、spec、工单——每一步的成果都是文件。 所以换会话不可怕（第 2 课），流程接得上。
  3. 每站都有"完成信号"：能说清"这一步完了"再往前走—— spec 确认了、工单检查过了、审查报告看了。含糊过关，后面会加倍偿还。

4.4复盘：让系统变聪明

收尾不是"做完就散"——两个复盘技能让这套系统从每次工作里学习：

  • retro：回顾这次会话，按类别提改进建议（流程、检查、标准……）；
  • reflect：发现重复出现的劳动，建议把它沉淀成可复用的资产（技能、配置、模板）。

你的动作只有一句话："复盘一下"。建议由它出，采不采纳你说了算。 你正在读的这门课、你的学习档案，就是同一思路的产物——把经验变成文件。

4.5随堂小测

七道题，覆盖每一站。点击作答，立即判分。

4.6立即动手

立即动手 · TRY IT NOW

  1. 拿一个真实的小需求走一遍完整流程（单窗口折叠版即可）；
  2. 记录每一站的产出物：它给了你什么？问了你什么？
  3. 做完让它"复盘一下"，看看建议里有没有能落进配置或习惯的东西。

4.7小结

三句话记住这一课：主链五站，每站都有落盘产出和你的动作； 小任务走折叠版，流程按任务重量裁剪； 收尾复盘让系统越用越聪明——你的活只有一句"复盘一下"。
